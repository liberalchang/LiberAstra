# 通知

「设置 → 通知」把任务完成、失败、取消和运行进度推送到 Telegram、飞书、钉钉、Bark 或 Webhook。第一版是单用户：所有渠道和规则都属于当前账号（管理员）。

通知是异步的：任务结束时先写入投递队列，后台 worker 再发送。发送失败按渠道重试，不影响任务本身。

## 快速开始

1. 在「通用」里选择推送语言；需要消息里的任务链接时填写公开访问地址。
2. 在「渠道」新建一个渠道，填好地址/密钥，保存后点「测试」。
3. 在「规则」新建规则，勾选事件和渠道。默认只推成功和失败；需要进度时再勾「运行进度」。
4. 跑一个任务，在「投递记录」里确认状态。

## 通用

| 配置 | 作用 | 怎么填 |
|------|------|--------|
| 推送语言 | 决定所有通知消息的文案语言 | 中文或 English。全局生效，不跟随界面语言；已入队/已发送的正文不会重渲染 |
| 出站代理 | 让通知请求走代理，常用于访问 Telegram | 例如 `http://127.0.0.1:7890`。留空时沿用 `HTTP_PROXY` / `HTTPS_PROXY` / `NO_PROXY`；只支持 http/https，不支持用户名密码和 SOCKS5 |
| 公开访问地址 | 生成消息里的任务/画布链接 | 例如 `http://10.0.0.2:8000` 或你的域名。留空则消息不带链接 |

代理注意：

- 显式填写全局代理会对所有渠道生效。`NO_PROXY` 在显式代理下不一定生效。
- 同时需要「Telegram 走代理、局域网 Webhook 直连」时，可以在渠道里关闭「使用全局代理」；每个渠道只控制是否使用全局代理，不能单独填代理地址。
- TLS 默认校验证书。自签名 HTTPS 的内网服务暂不支持关闭校验；请改用 HTTP 或受信任证书。

## 渠道

每个渠道共用的字段：

| 字段 | 作用 | 默认/范围 |
|------|------|-----------|
| 名称 | 展示名，同一账号下不能重复 | 必填 |
| 类型 | Telegram / 飞书 / 钉钉 / Bark / Webhook | 创建后不能改；换类型请新建 |
| 启用 | 停用后不再产生新投递，已排队投递会跳过 | 默认开 |
| 最大尝试次数 | 发送失败最多尝试几次 | 默认 3，范围 1–10 |
| 退避基数 | 失败后的重试等待基数，按指数增长，封顶 1 小时 | 默认 30 秒 |
| 超时 | 单次 HTTP 请求超时 | 默认 10 秒，范围 1–60 |
| 使用全局代理 | 这个渠道是否走「通用」里的全局代理 | 默认开；关闭后该渠道直连，连环境变量代理也不走 |

密钥类字段（Bot Token、Webhook secret、Bark Device Key、HMAC secret）加密存储，界面只显示尾 4 位或 host。编辑时这些字段和含 token 的地址只显示掩码（例如 `****ABCD`、`https://host/***`）；输入框留空保存会保留原值。Bark 服务器地址不是密钥，会完整回填。飞书/钉钉/Webhook 的可选密钥可以勾选「清空可选密钥」删掉。

### Telegram

| 字段 | 作用 | 怎么获取 |
|------|------|----------|
| Bot Token | 机器人凭据 | BotFather 给的是「数字 bot ID + 冒号 + 密钥」，例如 `123456789:AAE...`。冒号在中间，不要在开头加冒号，也不要只粘贴冒号后的密钥 |
| Chat ID | 消息发到哪个聊天 | 这是接收消息的聊天 ID，**不是 bot ID**。可点输入框右侧的搜索图标自动获取；也可以私聊先用 `@userinfobot` 查自己的数字 ID，并先给 bot 发 `/start`。群/频道通常是负数 `-100...` |
| 解析模式 | 消息格式 | HTML 或 MarkdownV2；默认 HTML |
| 关闭链接预览 | 不在消息下方展开链接卡片 | 默认开 |

保存后点「测试」。机器人必须已经进入目标群，或你已先给机器人发过消息。

**自动获取 Chat ID**：点 Chat ID 右侧的搜索图标，应用会用当前 Bot Token 读取机器人最近收到的消息：

- 新建渠道时使用表单里刚填的 Token；编辑渠道且 Token 留空时使用已保存的 Token。
- 只有一个候选会话时直接填入；多个候选时列出私聊、群和频道，点一个填入。
- 机器人必须先收到消息：私聊给它发 `/start`；群/频道先把它拉进去并发一条消息，频道需要管理员权限。
- 只读取未确认的最近更新（通常 24 小时内），不会消费或清除消息；如果机器人启用了 Webhook，`getUpdates` 会冲突，需要先关闭 Webhook。
- 找不到会话时不会改动 Chat ID，并提示先给机器人发消息。

### 飞书

| 字段 | 作用 | 怎么获取 |
|------|------|----------|
| Webhook 地址 | 群自定义机器人地址 | 飞书群 → 设置 → 群机器人 → 添加自定义机器人 → 复制 webhook |
| 加签密钥（可选） | 开启「签名校验」时填写 | 与 webhook 同一设置页 |

### 钉钉

| 字段 | 作用 | 怎么获取 |
|------|------|----------|
| Webhook 地址 | 群自定义机器人地址 | 钉钉群 → 群设置 → 智能群助手 → 添加机器人 → 自定义 → 复制 webhook |
| 加签密钥（可选） | 开启「加签」时填写 | 与 webhook 同一设置页 |
| @ 手机号 | 消息里 @ 指定人 | 逗号分隔，例如 `13800000000,13900000000` |
| @ 所有人 | 消息里 @ 所有人 | 默认关；群设置可能限制 |

### Bark

| 字段 | 作用 | 默认 |
|------|------|------|
| 服务器地址 | Bark 服务地址 | `https://api.day.app` |
| Device Key | 设备的推送 key | 必填 |
| 分组（可选） | iOS 通知分组 | 空 |
| 铃声（可选） | 通知铃声 | 空 |

### Webhook

| 字段 | 作用 | 说明 |
|------|------|------|
| Webhook 地址 | 接收端 URL | 只支持 http/https；第一版只发 POST |
| 自定义 headers | 附加请求头 | JSON 对象，例如 `{"X-Token":"..."}`；`Host`、`Content-Length` 等保留头会被忽略 |
| HMAC 密钥（可选） | 给请求签名 | 有值时带 `X-LiberAstra-Signature: sha256=...`、`X-LiberAstra-Timestamp`、`X-LiberAstra-Delivery` |
| Body 模板（可选） | 自定义 JSON 正文 | 占位符：`{title}` `{body}` `{event}` `{job_id}` `{link}` `{delivery_id}`；渲染后必须是 JSON 对象 |

不填 Body 模板时，默认发送：

```json
{
  "event": "job.succeeded",
  "title": "任务标题",
  "body": "消息正文",
  "job": {"id": "job-id"},
  "link": "http://example/jobs/job-id",
  "timestamp": "2026-11-10T12:00:00+00:00"
}
```

接收端可以用 `X-LiberAstra-Delivery` 做幂等去重。

## 规则

| 配置 | 作用 | 说明 |
|------|------|------|
| 名称 | 规则展示名，同一账号下不能重复 | 必填 |
| 启用 | 停用后不再产生新投递，已排队投递会跳过 | 重新启用不会补发停用期间的历史任务 |
| 事件 | 哪些任务状态触发通知 | 成功、失败、取消、运行进度；默认成功+失败，进度默认关 |
| 进度间隔 | 进度摘要的生成间隔 | 最小 60 秒，默认 900 秒；关闭进度请取消勾选「运行进度」 |
| 每摘要最多任务数 | 一条进度消息最多列几个任务 | 默认 10，范围 1–50；超出显示「还有 N 个」 |
| 任务类型过滤 | 只通知指定 Job 类型 | 逗号分隔，例如 `video.motion, canvas.run`；留空=全部，但画布子节点默认跳过 |
| 投递渠道 | 这条规则发到哪些渠道 | 至少选一个 |
| 启用静默时段 | 某段时间不推进度摘要 | 只抑制进度；完成/失败/取消仍立即发 |
| 静默开始/结束 | 静默时段边界 | 左闭右开，支持跨午夜 |
| 时区 | 静默时段的 IANA 时区 | 例如 `Asia/Shanghai`；Windows 需要带 tzdata |
| 完成消息带输出链接 | 完成/失败/取消消息里附任务链接 | 需要「公开访问地址」；留空则无链接 |
| 高级：模板覆盖 | 自定义成功/失败/进度正文 | 留空用默认模板 |

### 任务类型过滤

规则是跨渠道的：一条规则可以同时选 Telegram 和 Bark。渠道列表按类型分组，但不会因为规则名称或已选渠道而隐藏其他类型；需要每个渠道使用不同事件或间隔时，请分别建规则。

- 留空表示全部顶层任务。
- 画布每个功能性节点是独立的 `canvas.node` Job，默认不逐节点通知；整个画布结束时发一条 `canvas.run` 汇总。
- 需要调试逐节点通知时，把 `canvas.node` 显式写进过滤列表。
- 想只收某类任务（例如动作迁移），填 `video.motion`。

### 模板占位符

成功/失败模板：

- `{job_name}`：任务标题
- `{status}`：状态
- `{progress}`：进度百分比
- `{elapsed}`：耗时
- `{error}`：错误摘要（已脱敏）
- `{link}`：任务链接
- `{outputs}`：输出数量

进度模板：

- `{count}`：本摘要任务数
- `{running}`：运行中数量
- `{queued}`：排队数量
- `{jobs}`：默认生成的逐任务列表
- `{link}`：任务中心链接

### 进度摘要与静默

- 没有活动任务时不推送。
- 每个规则在每个间隔桶最多生成一条摘要。
- 画布的进度会聚合成一条，不会每个节点刷一行。
- 静默时段只作用于进度；任务完成、失败、取消不受影响。

## 投递记录

「投递记录」显示最近 100 条：

| 状态 | 含义 |
|------|------|
| `pending` | 排队中 |
| `sending` | 正在发送 |
| `sent` | 已发送 |
| `failed` | 重试耗尽或不可重试的 4xx |
| `skipped` | 规则/渠道删除或停用等原因跳过 |

可以按状态筛选。`failed` / `skipped` 且目标仍存在时可以点「重试」。投递记录保留 30 天，只清理终态记录。

## 画布与批量

- 画布运行会创建一条 `canvas.run` 汇总 Job；默认只发一条完成/失败/取消消息。
- 汇总 Job 不在任务列表显示，也不能取消或重试。
- 批量任务目前仍按单个 Job 通知；如不想逐条收，可用任务类型过滤。批次级汇总后续再加。

## 常见问题

**测试消息收不到。** 检查 Bot Token / Chat ID / webhook、机器人是否在群里、飞书/钉钉是否开了加签、代理是否可达。Telegram 在国内通常需要代理。

**任务完成但没有通知。** 依次检查：规则是否启用、事件是否勾选、渠道是否启用、任务类型过滤是否排除了该 Job、进度是否受静默时段影响、公开地址是否为空（只影响链接）。画布节点默认不逐节点通知。

**Telegram 报 404 Not Found。** 多数是 Bot Token 格式不对或已失效：完整 token 必须包含数字 bot ID、一个冒号、后面的密钥；不要把冒号放最前面，也不要只粘贴后半段。

**Telegram 的 Chat ID 填成了 bot ID。** Bot Token 冒号前的数字是 bot 自己的 ID，不是聊天 ID；请填自己的用户 ID，或群/频道的负数 ID。填 bot ID 时 Telegram 会返回 403「bot can't send messages to the bot」。

**自动获取 Chat ID 找不到会话。** 先确认 bot 已收到目标会话的消息：私聊发 `/start`，群/频道把 bot 拉进去并发一条消息。只填了 Token 但还没保存的新渠道也可以获取；编辑渠道时 Token 留空会用已保存的 Token。

**重复收到。** 通知是 at-least-once：第一次请求可能已送达但响应丢失，重试会重复。Webhook 接收端用 `X-LiberAstra-Delivery` 去重。

**4xx 会重试吗。** 不会，408/429 除外。429 会优先按 `Retry-After` 等待，最长 1 小时。

**改了密钥但没生效。** 编辑时密钥留空表示保留原值；需要替换就填新值。飞书/钉钉/Webhook 的可选密钥可以勾「清空可选密钥」。

**自签名 HTTPS。** 第一版默认校验证书，不提供每渠道关闭校验。请改用 HTTP 或受信任证书。

**时区不生效。** 确认填写的是 IANA 时区名；Windows 安装包需要 tzdata。无效时区会回退，界面会提示保存失败。

## 安全

- 渠道密钥用 Fernet 加密落库，API 只返回掩码；日志和错误摘要会脱敏。
- API Token 视同管理员权限；不要把 Token 发给不可信 Agent。
- Webhook 地址只允许 http/https，不跟随跨域重定向；第一版由管理员配置。
